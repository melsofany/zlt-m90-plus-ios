# ZLT M90 Plus — تطبيق Android أصلي (Kotlin + Jetpack Compose)

تطبيق أندرويد لإدارة جهاز **ZLT M90 Plus** عبر شبكة Wi-Fi المحلية. هذا هو التسليم الأساسي المطلوب (نسخة APK)، وهو تحويل كامل للمشروع الأولي SwiftUI الموجود في جذر المستودع.

الواجهة عربية بالكامل، تدعم الاتجاه من اليمين إلى اليسار، وتعمل في الوضعين الفاتح والداكن، مع دعم Dynamic Type (تكبير الخط من إعدادات النظام) ووصف VoiceOver/TalkBack لكل عنصر.

## البناء

### المتطلبات
- JDK 17 أو 21.
- Android SDK مع `compileSdk 34` و`build-tools 34.0.0`.
- لا حاجة إلى Android Studio؛ يمكن البناء من سطر الأوامر.

### الأوامر

```bash
cd android

# نسخة التطوير
./gradlew assembleDebug

# نسخة الإصدار
./gradlew assembleRelease

# فحص Lint
./gradlew lintDebug

# جميع الاختبارات (54 اختبارًا، منها اختبارات رسم بصرية)
./gradlew testDebugUnitTest
```

إن لم يكن `ANDROID_HOME` معدًا، أنشئ `android/local.properties`:

```properties
sdk.dir=/path/to/android-sdk
```

### مكان ملف الـ APK

```
app/build/outputs/apk/debug/app-debug.apk
app/build/outputs/apk/release/app-release.apk
```

### صور الشاشات الناتجة عن الاختبارات

اختبارات `VisualSnapshotTest` ترسم الشاشات فعليًا وتكتب صور PNG في:

```
app/build/reports/screenshots/
```

وتشمل: `dashboard-light.png`، `dashboard-dark.png`، `connect-rtl.png`، `connect-ltr.png`، ولقطات لشاشة صغيرة `320×480dp` وشاشة كبيرة `480×1000dp`.

### توقيع نسخة الإصدار

نسخة `release` موقّعة بمفتاح debug افتراضيًا حتى يتم إدخال مفتاح إصدار حقيقي. لتفعيل التوقيع الحقيقي:

```bash
cp android/keystore.properties.example android/keystore.properties
# ثم املأ المسار وكلمات المرور، وأنشئ المفتاح إن لم يكن موجودًا:
keytool -genkeypair -v -keystore zlt-release.jks -alias zlt -keyalg RSA -keysize 2048 -validity 10000
```

`keystore.properties` وملفات `.jks` مستثناة من Git.

للتثبيت على هاتف متصل بالـ USB:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### التكامل المستمر

`.github/workflows/android.yml` يشغّل الاختبارات وLint ويبني النسختين، ويرفع الـ APK والصور الناتجة كـ Artifacts.

## التشغيل على جهاز حقيقي

1. شغّل جهاز ZLT M90 Plus وانتظر حتى تكتمل الإقلاع.
2. من الهاتف، اتصل بشبكة Wi-Fi الخاصة بالجهاز (الاسم على الملصق، وغالبًا كلمة المرور مكتوبة عليه).
3. افتح لوحة إدارة الجهاز في متصفح الهاتف عبر `http://192.168.0.1` — إن لم تفتح، جرّب العنوان المكتوب على الملصق أو `192.168.1.1`.
4. إذا لم تفتح اللوحة، استخدم زر **اكتشاف الجهاز تلقائيًا** في التطبيق.
5. أدخل اسم المستخدم وكلمة المرور بعد التحقق منهما من اللوحة، ثم اضغط **اتصال بالجهاز**.

> التطبيق لا يخمّن كلمة المرور ولا يخزّنها في `UserDefaults`/`SharedPreferences` نصًا صريحًا. كلمة المرور تُستخدم للطلب فقط، ورمز الجلسة وحده يُحفظ مشفّرًا بمفتاح AES-256 داخل Android Keystore.

### ربط مسارات Firmware الحقيقية

مسارات API في هذا المشروع مبنية على المسارات الشائعة لعائلة برامج LuCI التي تعتمدها أجهزة ZLT. **قد تختلف حسب إصدار Firmware أو مزود الخدمة**، لذلك كل المسارات وأسماء الحقول موجودة في ملف واحد:

```
app/src/main/assets/router_routes.json
```

خطوات الضبط:

1. افتح لوحة إدارة الجهاز في المتصفح على سطح المكتب.
2. من أدوات المطوّر (Network)، سجّل الطلبات التي ترسلها اللوحة عند العرض، وعند تسجيل الدخول.
3. انسخ المسار وطريقة الطلب (GET/POST) وأسماء الحقول الفعلية إلى `router_routes.json`.
4. إن كانت الاستجابة XML، غيّر `"encoding": "json"` إلى `"xml"` — المحلّل يدعم الصيغتين.
5. أعد البناء. لا حاجة لتعديل أي كود Kotlin.

أسماء الحقول تُقرأ كقوائم مرادفات، فمثلًا `batteryPercent` يقبل `battery_percent` أو `batteryLevel` أو `battery` وهكذا، وهذا يقلل التعديل المطلوب بين إصدارات Firmware.

## وضع العرض التجريبي (Demo)

لا يحتوي التطبيق على جهاز حقيقي أثناء التطوير، لذلك وفّرنا `MockRouterApi` وشاشة الدخول بها زر **تفعيل وضع العرض التجريبي**.

قواعد الوضع التجريبي:

- لا يعمل تلقائيًا أبدًا؛ يحتاج ضغطًا صريحًا من المستخدم.
- تظهر شارة **بيانات تجريبية** في الشريط العلوي طوال فترة تفعيله.
- لا تُستخدم قيمه في أي شاشة إنتاج على أنها قيم حقيقية.

داخل `MockRouterApi` توجد سيناريوهات جاهزة (بطارية غير متاحة، شحن، نقص قراءات، جهاز بلا باقة، …) لاختبار حالات الفشل بصريًا.

## الصورة: مهم

المستودع **لا يحتوي على صورة رسمية مرخّصة** لجهاز ZLT M90 Plus، والتطبيق لا يعرض صورة عشوائية من الإنترنت على أنها صورة المنتج.

- الوضع الافتراضي: رسم توضيحي يحمل وسم **«صورة مؤقتة»** بشكل ظاهر.
- لعرض الصورة الحقيقية: ضع ملفًا باسم `zlt_m90_plus_device.png` في:

  ```
  app/src/main/assets/zlt_m90_plus_device.png
  ```

  وسيُستخدم تلقائيًا بدون أي تعديل في الكود (راجع `ui/components/DeviceImage.kt`).

استبدل الرسم في `app/src/main/res/drawable/zlt_m90_plus_device.xml` إن أردت شكلًا أوضح مؤقتًا.

## قواعد عرض البيانات (الأهم في هذا المشروع)

**لا يُعرض رقم على أنه حقيقي إذا لم يرجعه الجهاز أو مزود الخدمة.**

كل نموذج بيانات يحمل حقل `source` من: `ROUTER`، `CARRIER`، `MANUAL`، `ESTIMATED`، `UNAVAILABLE`، ويظهر بجانب كل قيمة وسْم عربي يوضح مصدرها. عند غياب المعلومة تُعرض `غير متاحة من الجهاز` مع سبب مختصر، لا صفر ولا قيمة تقديرية مضللة.

تقدير الوقت المتبقي في `BatteryEstimator`:

- يحتاج قراءتين على الأقل بفاصل زمني كافٍ، ويُرفض أثناء الشحن أو عند القفزات غير المنطقية.
- إن أرسل الجهاز زمنًا فعليًا، يُعرض أولًا مع وسم **«حسب الجهاز»**.
- إن حُسب داخل التطبيق، يظهر بوضوح **«تقديري»** مع النص: «الوقت المتبقي تقديري وقد يختلف حسب قوة الإشارة وعدد الأجهزة المتصلة واستهلاك البيانات.»
- إن لم تكفِ القراءات: **«لا يمكن التقدير حاليًا»**.

## مصفوفة دعم الميزات

| الميزة | مصدرها | ملاحظة |
| --- | --- | --- |
| نسبة البطارية | Firmware | مسارات `battery` في `router_routes.json` |
| حالة الشحن | Firmware | تُقرأ من حقول منطقية بصيغ متعددة |
| الزمن المتبقي الفعلي | Firmware | عرض اختياري؛ ليس كل إصدار Firmware يرسله |
| الزمن التقديري | التطبيق (تقديري) | يحتاج قراءتين على الأقل |
| حالة الإنترنت | Firmware + اختبار حقيقي | نجاح فتح صفحة الراوتر **لا** يُعتبر دليلًا على وجود إنترنت |
| اسم المشغل / نوع الشبكة | Firmware أو مزود الخدمة | كثير من الأجهزة لا ترسل اسم المشغل |
| قوة الإشارة | Firmware | تُعرض نصًا ونسبة وديسيبل إن توفرت |
| بيانات الباقة | مزود الخدمة أو إدخال يدوي | غالبًا **غير متاحة من الجهاز**؛ استخدم شاشة «إعداد الباقة» |
| الأجهزة المتصلة | Firmware | تعتمد على وجود قائمة العملاء في اللوحة |
| تغيير Wi-Fi وإعادة التشغيل | Firmware | خلف تأكيد إلزامي، ومُعطّلة في الوضع التجريبي |

## الأمان والخصوصية

- كل الاتصالات محلية عبر LAN افتراضيًا؛ لا يوجد أي إرسال لخادم خارجي.
- `cleartextTrafficPermitted="false"` عام، ويُسمح باستثناءات HTTP فقط لعناوين LAN الخاصة في `res/xml/network_security_config.xml`.
- لا تُسجَّل كلمات المرور أو رموز الجلسة أو بيانات الباقة في Logcat — لا يوجد أي `Log` في كود التطبيق.
- `android:allowBackup="false"` مع استثناءات في `data_extraction_rules.xml` لمنع نسخ ملفات الجلسة.
- العمليات المؤثرة (تغيير Wi-Fi، إعادة التشغيل) خلف نافذة تأكيد، وموقوفة في الوضع التجريبي حتى يتم التحقق من مسارات Firmware.

## الاختبارات

49 اختبار وحدة، تشمل:

- `BatteryEstimatorTest` — النسبة، الشحن، القراءات المتناقصة، عدم كفاية القراءات.
- `DataPlanCalculatorTest` — النسبة المستخدمة والمتبقي والأيام المتبقية.
- `ResponseParserTest` — JSON وXML، الحقول الناقصة، الحمولات التالفة، استخراج رمز الجلسة.
- `RouterRoutesConfigTest` — قراءة `router_routes.json`.
- `ModelDefaultsTest` / `SignalMappingTest` — القيم الافتراضية وتخطيط الإشارة.
- `MockRouterApiTest` — جميع السيناريوهات.
- `ScreenRenderTest` — يعرض الواجهات فعليًا عبر Robolectric ويتحقق من النصوص العربية، ومن قاعدة «غير متاحة» عند غياب البيانات، ومن العمل بالوضع الداكن واتجاه RTL.
- `VisualSnapshotTest` — يرسم الشاشات بمحرك Robolectric الرسومي الأصلي ويحلّل البكسلات الناتجة: يتحقق من ظهور المحتوى فعلًا في الوضعين الفاتح والداكن، ومن أن الاتجاه RTL يغيّر التخطيط فعلًا، ومن أن النص يكبر مع `fontScale`، ومن سلامة التخطيط على شاشة `320×480dp` وشاشة `480×1000dp`. ويحفظ الصور في `app/build/reports/screenshots/`.

```bash
./gradlew testDebugUnitTest
```

### ما لم يُختبر بعد

لم يُشغَّل التطبيق على جهاز ZLT M90 Plus فعلي ولا على محاكي بواجهة رسومية في هذه البيئة (لا يوجد `/dev/kvm`، والمحاكي غير متاح). لذلك:

- المسارات في `router_routes.json` تحتاج تحققًا ضد Firmware الجهاز الفعلي.
- اختبار TalkBack وقارئ الشاشة، والسلوك على شاشات الطي، يبقى مطلوبًا يدويًا.
- الصور الناتجة عن `VisualSnapshotTest` تغطي الوضعين وأحجام الشاشات، لكنها ليست بديلًا عن تشغيل حقيقي.

**لا يُعتبر هذا التطبيق جاهزًا للإنتاج قبل اختباره على جهاز ZLT M90 Plus حقيقي وبإصدارات Firmware مختلفة.**
